透過本案例的四項 EAGLE 2.0 系統操作任務，你將：

二、你的角色：監造工程師

在本系列任務中，你將扮演任泰技術顧問有限公司的監造工程師，負責監督「磺港溪再造步道整建工程」的施工品質、進度與安全。

2.1 監造工程師是誰？做什麼？

在公共工程中，「監造」是由主辦機關委託的工程顧問公司派駐現場的工程師，其角色介於業主（主辦機關）與承攬廠商（營造廠）之間。監造工程師的主要職責包括：

  1. 監督施工品質：確認承攬廠商是否依照設計圖說及規範施工，執行施工抽查、材料檢驗。
  2. 管控工程進度：記錄每日施工情形，核對預定與實際進度，發現落後時提出因應措施。
  3. 審核工程文件：審查承攬廠商送審的施工計畫、品質計畫、材料送審資料等。
  4. 維護工地安全：監督承攬廠商落實職業安全衛生管理，記錄並追蹤缺失改善。
  5. 編製監造報告：定期彙整施工情形，向主辦機關提報監造紀錄與建議。

三、什麼是「當責」？

「當責」（Accountability）與「負責」（Responsibility）不同。負責是完成被交付的工作；當責則是對最終結果負完全責任，即使過程中遇到困難，也要主動尋找解決方案，而不是等待他人指示。

在本系列任務中，「當責」的具體表現包括：

  1. 準確性：填寫的每一筆資料都必須經過確認，不能想當然耳地隨意填寫。
  2. 完整性：不遺漏任何必要的欄位或資訊，了解每個欄位存在的意義。
  3. 時效性：在規定時間內完成任務，理解工程現場「逾期」的嚴重性。
  4. 主動性：遇到不確定的問題時，主動查找資料、詢問 AI 助教或與同學討論，而非放棄或隨便填答。
  5. 反思性：完成任務後，回顧自己的過程，誠實面對不足之處，思考改進方法。
當責宣言 在開始任務之前，請你在心中對自己說：
「我是這個專案的監造工程師。我填寫的每一筆資料、做出的每一個判斷，都關係到這個工程的品質與安全。我將對我的工作成果負完全責任。」

系統以統一的側邊欄導航，提供以下主要功能模組：

1.5 任務執行步驟

步驟 A：新增專案

    • 說明：臺北市政府工務局水利工程處主辦之河岸步道整建工程
    • 專案代碼：H-111-03-111166
  3. 點擊「建立」按鈕，系統會自動將你設為該專案的管理員，並導向儀表板頁面。

步驟 B：填寫專案基本資料

  1. 從左側選單點擊「專案基本資料」。
  2. 點擊右上角「編輯」按鈕，切換為編輯模式。
  3. 依照開工報告表中的資料，填入以下欄位：

    工程名稱磺港溪再造步道整建工程（奇岩抽水站至西安橋）
    設計單位（依開工報告表填寫）
    監造單位任泰技術顧問有限公司
    施工廠商永溢營造股份有限公司
    工程概要河岸護岸整建、步道鋪面、景觀設施及排水設施改善工程

    工期（天）180
  4. 系統會自動計算「預定完工日期」。請確認計算結果是否為 112 年 7 月 28 日。
  5. 點擊「儲存」完成基本資料設定。
操作提示 填寫基本資料時，請務必對照開工報告表逐欄確認。特別注意「開工日期」與「工期」的填寫——這兩個欄位會連動儀表板的工期天數計算，以及施工日誌的自動帶入欄位。

步驟 C：匯入契約工項

  1. 從左側選單進入「施工管理」→「契約工項」。
  2. 在「契約工項匯入」分頁中，點擊「選擇檔案」按鈕，選取原契約 XML 檔案（磺港溪再造步道整建工程(奇岩抽水站至西安橋).xml）。
  3. 首次匯入時，「版本名稱」會自動填入「原契約」。點擊「上傳」按鈕，系統開始解析 XML 檔案內容。
  4. 匯入成功後，系統自動導向匯入明細頁面。請逐一確認以下項目是否正確匯入：
    • 壹、發包工程費（總金額 22,700,000 元）
    • 一（一）整備工程：包含機械拆除、瀝青混凝土面層刨除、廢棄物處理等工項
    • 一（二）土建景觀工程：包含混凝土、鋼筋、模板等主要結構工項
    • 確認各工項的項次、說明、單位、數量與單價是否與 XML 原始資料一致
什麼是 PCCES？ PCCES（公共工程經費電腦估價系統）是臺灣公共工程委員會建立的標準化系統，用於工程經費估算與契約工項管理。其匯出的 XML 格式是公共工程契約工項的標準交換格式，包含完整的詳細價目表結構（項次、品名、單位、數量、單價、複價）。本系統支援直接匯入 PCCES XML 格式檔案。

步驟 D：上傳預定進度計畫

  1. 從左側選單進入「施工管理」→「進度表」。
  2. 點擊「上傳進度計畫」區域的下載按鈕，取得系統提供的 Excel 範本。
  3. 開啟教材中的「進度曲線表.pdf」（16.進度表/進度曲線表.pdf），從 S 曲線中讀取各期的預定進度累計百分比。
  4. 在 Excel 範本中，依照讀取的數據填入各期預定進度百分比。
  5. 將填好的 Excel 檔案上傳至系統。系統解析後會自動繪製預定進度 S 曲線（藍色線）。
  6. 確認畫面上的 S 曲線與教材中的進度曲線表一致。
為什麼這一步很重要？ 預定進度 S 曲線是後續任務 2（施工日誌）中比較「預定進度 vs 實際進度」的基準線。如果這條線沒有正確設定，你在填寫日誌時將無法判斷工程進度是超前還是落後。

1.6 提示問題

  1. 工程契約中的「詳細價目表」與「單價分析表」各扮演什麼角色？兩者之間是什麼關係？
  2. 「決標金額」與「契約金額」是否一定相同？如果後續有變更設計，金額會如何變化？
  3. 如果在專案建立階段，契約工項的數量輸入錯誤（例如多了一個零），後續可能造成什麼連鎖影響？
  4. 監造工程師為什麼需要了解契約工項的細節？這與他的監造職責有什麼關聯？
  5. 預定進度 S 曲線的形狀為什麼通常呈現「慢—快—慢」的趨勢？這反映了工程施工的什麼特性？

1.7 自我檢核清單

  • 專案基本資料（工程名稱、單位、金額、工期、日期）與開工報告表完全一致。
  • 契約工項已透過 XML 正確匯入，項次、說明、單位、數量、單價均與原始資料吻合。
  • 預定進度計畫已上傳，系統可顯示正確的預定進度 S 曲線。
  • 儀表板上的「累計天數」與「整體進度」資訊顯示正常。

2.3 角色與責任

你身為監造工程師，填寫的是監造日報表第一聯。與承攬廠商填寫的施工日報（第二聯）不同，監造日報表記錄的是你「監督」施工的情形，而非你「執行」施工的情形。你的日報表需要反映：

  • 本日承攬廠商進行了哪些重要施工項目？

  • 預定進度與實際進度各為多少？是否有落差？
當責提醒 監造日報表是工程施工期間最重要的法律文件之一。在工程爭議、驗收糾紛甚至司法訴訟中，監造日報表常被引用作為關鍵證據。如果日報表記載不實（例如記載已施工但實際未施工），監造人員可能面臨偽造文書的法律責任。即使在本課程的模擬練習中，也請你以這樣的嚴謹態度對待每一份日報表。

步驟 C：計算每日預定進度與實際進度

關鍵問題 營造廠（公司內部）甘特圖的工程名稱跟契約的項目不一樣，為什麼？有沒有可能一樣？——這是因為公司內部的施工排程是以「工作面」或「施工階段」來規劃，而契約項目則是以「計價項目」來分類。兩者的分類邏輯不同，但透過 WBS 可以建立對應關係。理解這個差異，是成為合格工程師的重要一步。

3.5 任務執行步驟

步驟 A：CPM 分析

  1. 根據工程網狀圖，繪製（或整理出）本工程的前置關係圖（Activity-on-Node 或 Activity-on-Arrow）。
  2. 標示每項工作的工期，並執行前推（Forward Pass）與後推（Backward Pass）計算：
    • 最早開始時間（ES）與最早完成時間（EF）
    • 最晚開始時間（LS）與最晚完成時間（LF）
    • 總浮時（TF）= LS - ES 或 LF - EF
  3. 辨識要徑（Critical Path）：浮時為零的路徑。
  4. 列出要徑上的工作項目，標示哪些項目在工程進度 30% 時已經在執行或即將開始。

步驟 B：EVM 分析

  1. 以契約金額為基礎，建立 EVM 分析表。選定分析的時間點（建議以「工程進度 30%」作為分析時間點）。
  2. 計算各指標：
    指標公式意義
    PV（計畫值）截至分析時間點，預定應完成工作的預算金額我們原本計畫做多少？
    EV（實獲值）截至分析時間點，實際完成工作的預算金額我們實際做了多少？
    AC（實際成本）截至分析時間點，實際花費的金額我們花了多少錢？
    SV（進度偏差）EV - PV正值=超前，負值=落後
    CV（成本偏差）EV - AC正值=節省，負值=超支
    SPI（進度績效指標）EV ÷ PV>1 超前，<1 落後
    CPI（成本績效指標）EV ÷ AC>1 節省，<1 超支
  3. 根據估驗計價資料（9.估驗計價/磺港C-C(1).pdf 等），交叉比對 EV 與 AC 的計算結果。

步驟 C：在 EAGLE 2.0 中檢視與驗證進度分析

  1. 進入系統的「施工管理」→「進度表」，檢視你在任務 2 中累積的進度數據。
  2. 在進度表頁面中，觀察 S 曲線圖：
    • 藍色線（預定進度）：你在任務 1 上傳的預定進度計畫。
    • 橙色線（實際進度）：根據施工日誌中的完成數量自動計算。
    • 兩線之間的色塊代表進度偏差——對照你的 EVM 分析中的 SV 與 SPI。
  3. 在進度資訊表中，確認各期的預定百分比、實際百分比與偏差數值，驗證是否與你手算的 EVM 結果一致。
  4. 若需修正進度數據，可點擊「編輯進度數據」按鈕直接在表中調整。
操作提示 EAGLE 2.0 的進度表提供的是數據化的進度比較圖。你的 CPM/EVM 分析報告（含原因分析與建議）請另以文件方式撰寫，作為本任務的產出。

步驟 D：分析變更設計對進度的影響

  1. 閱讀「第 1 次變更設計 CSV」與「工程變更明細表」，了解本工程的契約變更內容：
    • 原契約金額：新臺幣 22,700,000 元
    • 變更後契約金額：新臺幣 14,261,156 元
    • 金額減少了約 37%
  2. 比對原契約與變更設計，分析：
    • 哪些工項被刪除或大幅減少？哪些工項是新增的？
    • 被刪除的工項是否在要徑上？如果是，對工期有什麼影響？
    • 變更設計發生在工程的哪個階段？對已完成的工作有影響嗎？
  3. 思考 EVM 分析中的關鍵問題：變更設計後，BAC（完工預算）應該用原契約金額（22,700,000 元）還是變更後金額（14,261,156 元）？你的選擇會如何影響 SPI 和 CPI 的計算結果？
當責思考 變更設計在公共工程中很常見，但它不只是「改幾個數字」那麼簡單。變更設計會影響工程進度基準、成本預算、施工排程，甚至合約關係。身為監造工程師，你必須能夠分析變更設計的連鎖影響，並向主辦機關提出專業建議。這正是「以數據為基礎的工程管理決策能力」的核心展現。

4.2 學習標的

  1. 理解公共工程三級品管制度的架構（承攬廠商自主檢查 → 監造單位查驗 → 主辦機關抽驗）。

4.5 背景知識：三級品管與自主檢查

公共工程的三級品管制度是確保工程品質的核心機制：

層級執行單位內容
第一級承攬廠商（營造廠）施工自主檢查：承攬廠商在每個施工階段完成後，依據自主檢查表逐項檢核，確認品質符合規範後，報請監造查驗。
第二級監造單位（顧問公司）監造查驗：監造工程師接到承攬廠商的查驗請求後，到場進行抽查確認，填寫施工抽查紀錄表。
第三級主辦機關機關抽驗：主辦機關不定期到場抽驗，確認施工品質符合設計要求。

步驟 A：研讀自主檢查樣板

  1. 開啟自主檢查樣板資料夾（13.自主檢查類型/自主檢查樣板），瀏覽各類工程的檢查表。

  3. 理解每份檢查表中各查核項目的意義。例如，鋼筋查核表中「鋼筋號數、間距是否與圖說相符」這個項目，你需要理解為什麼鋼筋間距的正確性如此重要。

步驟 B：研讀歷史查核紀錄

  1. 開啟歷史自主檢查紀錄（3.自主檢查/C標抽查表.pdf），了解本工程實際執行過的查核內容。
  2. 注意觀察：
    • 查核頻率：多久執行一次查核？
    • 查核範圍：每次查核涵蓋哪些項目？
    • 查核結果：是否有發現不合格項目？如何處理？

步驟 C：在 EAGLE 2.0 中匯入檢查樣板

  1. 從左側選單進入「施工管理」→「自主檢查」。
  2. 點擊「匯入樣板」按鈕，系統會彈出樣板目錄對話框。
  3. 從系統提供的預設樣板中，勾選適用於本工程的檢查項目。參照監造計畫中的施工抽查程序，至少應包含：測量放樣、鋼筋工程、模板工程、混凝土工程、植筋工程等。
  4. 點擊「匯入」完成。匯入後，樣板清單頁面會顯示你匯入的所有檢查類型。

步驟 D：在 EAGLE 2.0 中填寫自主查核表

  1. 在樣板清單中，點擊欲執行檢查的樣板（例如「鋼筋工程」）。
  2. 點擊「新增檢查」建立新的檢查紀錄。
  3. 依據歷史查核紀錄的內容，以監造工程師的視角填寫各查核項目：
    • 填寫檢查日期及檢查人員資訊
    • 逐項勾選查核結果（合格／不合格／不適用）
    • 對於不合格的項目，可上傳現場照片作為紀錄
    • 填寫監造意見與備註
  4. 點擊「儲存」完成檢查紀錄。
  5. 重複以上步驟，完成至少 3 種不同類型的查核表（例如：測量放樣、鋼筋、混凝土）。
操作提示
  • 在「新增查驗」時，分項工程名稱會根據你在任務 1 匯入的契約工項自動帶入，不需要手動輸入。
  • 下載查核表時，系統提供「單筆下載」和「總表下載」兩種方式，分別適用於個別查驗紀錄和彙整報告。

步驟 E：模擬缺失發現與改善（選做）

  1. 如果在查核過程中「發現缺失」（參考歷史缺失紀錄 4.缺失改善/），可進入缺失改善功能進行練習。
  2. 點選左側選單「施工管理」→「缺失改善」→「新增缺失」。
  3. 填寫缺失內容（缺失類別、缺失描述、位置、改善期限等），並上傳缺失照片。
  4. 追蹤改善狀態：待改善 → 已改善 → 已確認。
